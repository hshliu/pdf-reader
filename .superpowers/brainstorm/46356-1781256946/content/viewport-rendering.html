第四步：视口渲染策略 — 全量 vs 虚拟化

对于 200 页 PDF，把全部页面加载到 DOM 中会导致内存爆炸和滚动卡顿。EmbedPDF + Syncfusion 的最佳实践：只渲染视口内可见页 ± 缓冲区。

全量渲染（Eager）
Page 1 ← DOM里
Page 2 ← DOM里
Page 3 ← DOM里
Page 4 ← 视口内
Page 5 ← 视口内
Page 6 ← DOM里
...
Page 198 ← DOM里
Page 199 ← DOM里
Page 200 ← DOM里
200 DOM 节点 → 内存爆炸
视口渲染（Viewport-only + Virtual DOM）
↑ 滚出视口，DOM 已回收
Page 3 ← 缓冲区 (+1)
Page 4 ← 视口内
Page 5 ← 视口内
Page 6 ← 缓冲区 (+1)
↓ 占位符，DOM 未创建
只 5 个 DOM = 恒定内存

控制器设计

IntersectionObserver
监听 .page-segment 进出视口 → 更新 currentPage 状态 → 同步缩略图高亮
DOM Recycler
滚出 buffer 范围回收 DOM → 替换为 placeholder div → 维持滚动条高度
Pre-fetcher
预请求前后 5 页 HTML → 缓存到 Map → 滚动时从缓存取不用等网络
Scroll Debounce
快速滚动延迟渲染 100ms → 防止每分钟数百次 API 请求
A

视口渲染 + 虚拟化 (推荐)

IntersectionObserver + DOM 回收 + 缓冲区 + 预请求缓存 + 滚动消抖。内存恒定。

B

简单全量加载

打开 PDF 时全部渲染到 DOM。简单但 200 页时内存可能超 500MB。
